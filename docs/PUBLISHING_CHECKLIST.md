# Before publishing and sharing

Use this checklist when you are ready to share a portfolio link with an employer, collaborator, lecturer or client.

## Content

- [ ] Replace or clearly identify the starter's example projects.
- [ ] Check your name, introduction, About page and intentional contact details.
- [ ] Ensure projects you want public have `draft: false`.
- [ ] Explain your individual role in collaborative work.
- [ ] Check spelling, headings and link destinations.
- [ ] Confirm you have permission to publish images, participant information and project material.

## Images and readability

- [ ] Every cover filename matches its `cover:` value exactly.
- [ ] Images are compressed to reasonable sizes without losing essential detail.
- [ ] Informative images have meaningful alternative text; decorative images are not described unnecessarily.
- [ ] Text remains legible against your chosen accent and background.
- [ ] Check the homepage, Work, About and one case study on a phone-sized viewport.
- [ ] Use the Tab key to navigate links and buttons; focus should remain visible.

## Publishing

- [ ] GitHub **Settings → Pages** uses **GitHub Actions**.
- [ ] The latest **Publish portfolio** run is green.
- [ ] The public URL works in a private/incognito browser window.
- [ ] Project links, covers and contact links work on the live site.
- [ ] You are looking at the correct branch and the latest deployed commit.

A portfolio can evolve. Publish a coherent first version, then improve it incrementally. If a build fails, use [Troubleshooting](TROUBLESHOOTING.md) before changing configuration files.
